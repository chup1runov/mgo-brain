# Восстановление проекта и запуск нового чата

## Новый чат

Передайте одну инструкцию:

> Продолжаем MGO Brain в `chup1runov/mgo-brain`. Прочитай актуальный main и START_HERE_RU.md, затем docs/CHAT_HANDOFF_RU.md, docs/AUDIT_2026-09-19_RU.md и docs/REMAINING_WORK_RU.md. Проверь SHA и CI. У нас Microcar M.Go / F8 0.5 2017 Progress ACT / LDW502; физические CAN-пара, распиновка и датчики ещё не подтверждены. Всё существенное обновляй в GitHub. Не смешивай с другими проектами. Не принимай симуляцию/макет за реальную диагностику и не объявляй аппаратную готовность по зелёному pytest. Сначала предложи и выполни один проверяемый следующий шаг в пределах согласованной задачи.

## Локальный программный стенд

Это инструкция запуска исходников, не монтажная процедура:

```bash
git clone https://github.com/chup1runov/mgo-brain.git
cd mgo-brain
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev,analytics]'
pytest -q
mgo-bench-smoke
MGO_BRAIN_SOURCES_FILE="$PWD/config/sources-bench.json" MGO_BRAIN_DATA_DIR="$PWD/data" MGO_AI_PROVIDER=local mgo-brain
```

В браузере этого компьютера: `http://127.0.0.1:8080/`. По умолчанию доступ локальный. Для телефона нужна отдельно согласованная сеть и bind-настройка; не выставлять порт наружу. Изолированная LAN, HTTPS и авторизация ещё требуют настройки. PWA/wake-lock не обещаны на обычном `http://mgo.local`.

После аудита данные разделены внутри `MGO_BRAIN_DATA_DIR` на `simulator`, `bench`, `vehicle`. Старую корневую базу не удаляйте: она не мигрируется автоматически в базу реального автомобиля. Производственную конфигурацию/телеметрию хранить вне Git.

## Воспроизводимые проверки

```bash
python -m compileall -q mgo_brain tests
python tools/repository_audit.py
pytest -q
mgo-bench-smoke --scenario low_oil_pressure
```

Для browser audit нужна установленная Playwright/Chromium и запущенный локальный backend; workflow Repository audit показывает точные команды и сохраняет артефакты. Не считать статическую проверку строк HTML эквивалентом работающего интерфейса.

## Резервирование

Исходники: Git-клон плюс отдельная резервная копия в другом месте. Runtime-данные и deployment-secrets хранить приватно. Runtime: `mgo-backup --output <путь-вне-data-и-config>/backup.tar.gz` и проверка восстановления. Архив может содержать чувствительные данные; хранить приватно/с шифрованием. Живая запись телеметрии и незавершённые файлы требуют отдельного recovery-теста; согласованный SQLite backup не делает все произвольные файлы атомарными.

## Что не нужно восстанавливать по памяти

Не восстанавливать цвета проводов, bitrate, резьбы и CAN ID из примеров чата. Их ещё не измеряли. Не запускать экспериментальные аппаратные источники только потому, что существует класс адаптера. Не ставить облачный API-ключ в README/.env репозитория. Модель облачного API задаётся явно после проверки доступности в аккаунте; локальный режим не требует API.
